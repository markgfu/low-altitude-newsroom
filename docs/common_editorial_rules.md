# 通用日报编辑规则

适用于所有主题；专业范围、栏目与核验重点读取当前主题配置。低空另沿用`editorial_rules.md`，其他主题不继承低空专业限定。

1. 标题从已经核验的本期核心新闻生成，准确保留主体与阶段；末尾使用主题名称和日期。今日总结一个自然段，通常2—3句话、100—180字。
2. 每条为事实标题、一个自然段摘要、来源机构、原文链接与真实发布日期。摘要通常80—150字，必要时至200字。栏目按主题配置顺序，空栏目省略，不设固定条数、不凑数。
3. 主窗口采用该主题上次成功截止至本次截止；首次默认24小时。新闻回看7日、学术回看30日，可在主题中配置。日精度日期不编造成精确时刻；回看材料不包装为当天新发生。
4. 先发现候选，再读原文与相关附件。搜索摘要、RSS条目与元数据不能冒充原文。无法核验的内容进入内部待核表，不直接刊登。
5. 核对主体、日期、金额、单位、状态和适用条件。区分母子公司、预算与成交额、意向与完成、草案与正式文件、企业自述与独立核验。主题专业要求写在`editorial_checks`并逐项落实。
6. 以事件去重，保留项目新阶段、文件新版本、政策更正等真实进展；跨主题分别判断相关性，各自保存历史。规范事件键包含主体或项目、事件类型与阶段/日期；不得为重复旧闻随意改键。
7. 学术报道保留作者归属、发表状态、实际阅读范围与关键限制；相关性不写成因果，模型或预测不写成已实现效果。只读摘要时明确标注；只有搜索片段不刊登。
8. 图片只从对应消息的可核验来源选择，实际打开检查内容、属性与使用条件，保留署名和水印。无合适图片不强配。使用现有render时先将核验后的原图放入稿件目录。
9. 公开正文不显示采集过程、缺口和内部状态。内部附记记录每个重要候选的采用、待核或排除原因，便于日后定位遗漏。与主题无关、无实质新增、重复或无法核验的内容不因“重要人物”而自动采用。
10. 输出供审核的待审稿，最后由用户决定发布。不自动向公众号群发、发送邮件或配置定时任务。

CLI的`check`只做格式检查。`accept`和`finish`依据编辑登记的查询、原文与交接材料进行一致性校验，不提供独立的事实认证，也不保证全网无遗漏。
