# 低空经济公众号每日资讯编辑规则

版本：1.11
制定日期：2026年10月15日  
更新日期：2026年10月20日  
适用范围：每日低空资讯的采集、筛选、分类、摘要与编排。

## 一、内容定位

每天优先收录发布日期较近的低空经济重要变化、项目进展与参与机会，保留关键事实，提供可核验出处。

选稿重点为政策动态与企业动态。政策、监管与空域规则的实质变化，以及企业研发、取证、融资、有效订单、交付和经营披露，优先进入标题、今日总结与正文。境外同类重要动态同样适用；栏目归类与固定顺序保持不变。权重体现为新闻价值与选稿优先级，不设固定条数、栏目比例或采购金额门槛。

主要面向低空企业、地方低空平台公司及相关研究人员。读者看完一期，应能了解当天值得关注的变化，并找到进一步核实或跟进的入口。

固定采用“**简短今日总结＋分类资讯**”结构。事实摘要是主体，不强制添加行业点评。

## 二、每日结构与栏目

### 1. 标题与今日总结

- 标题以当天最值得关注的具体新闻为主体，栏目名称和日期放在末尾。
- 默认采用多消息标题：`[核心新闻一]；[核心新闻二]；[可选的核心新闻三]｜低空日报 YYYY.MM.DD`。优先从不同栏目选择有信息价值的具体进展；当天只有一条重要消息时可使用单消息标题。
- 通常选2—3条核心新闻，兼顾政策或标准、企业及国外等不同动态，最重要、最具体的消息放在前面；不必覆盖所有栏目，不为拼标题加入低质量消息。
- 优先呈现有辨识度的地区或企业名称、具体动作、关键进展，必要时保留有意义的数字；不只写“政策动态”“企业动态”等栏目名。
- 标题须对应正文中已核验的消息，准确保留“拟建、招标、中标、取证、试运行、正式运营”等状态，不夸大范围、确定性或进展。
- 不使用缺乏依据的“重磅、炸裂、全面爆发”等词，不靠悬念或夸张承诺吸引点击；长机构名和文件全名可在不改变含义的前提下简写，完整名称放入正文。
- 标题在当期新闻筛选及摘要核验完成后生成，避免先定标题再拼凑内容。
- 结构示例：`[某地]飞服中心项目启动招标；[某企业]完成首批交付｜低空日报 YYYY.MM.DD`。示例仅演示格式，不能作为真实新闻直接使用。
- 标题下第一项内容为“**今日总结：**”，写成一段，通常2—3句话、100—180字，概括当期最值得关注的几类动态。
- 在选定当期新闻后再写总结，确保总结对应本期实际内容。
- 优先涵盖政策或标准、企业及国外等重要动态，保留关键主体、动作和阶段；不必逐条复述全期消息，也不强行覆盖全部栏目。
- 不逐一罗列所有栏目，不强行概括全国趋势，不使用缺少事实支撑的“全面爆发”“持续赋能”“发展提速”等表述。
- 不把“拟建、签约、试点”等阶段总结为“已落地、已运营”。

### 2. 栏目及顺序

| 顺序 | 固定栏目名称 | 收录内容 | 归类边界 |
| --- | --- | --- | --- |
| 1 | 低空政策动态 | 国家及地方政策、空域管理、运行规则、标准体系建设政策、扶持措施 | 区分征求意见稿、正式文件、实施细则与政策解读；具体技术标准归下一栏 |
| 2 | 低空标准动态 | 国内国家、行业、地方、团体及企业标准的立项、征求意见、发布、实施、修订或废止 | 标明标准编号、层级、发布主体、状态与适用范围；国际及国外标准进展集中进入国外动态 |
| 3 | 低空企业动态 | 产品研发、适航取证、订单交付、融资、企业合作及经营进展 | 产品发布、订单及融资归入本栏；具体工程建设和实际应用运行分别归入后两栏 |
| 4 | 基础设施与项目建设 | 飞服中心、起降点、通用机场、通信导航监视及气象设施、航路建设 | 重点交代建设主体、建设内容、所在地及项目阶段；设施建设类招标和中标也归本栏 |
| 5 | 低空应用动态 | 物流配送、农业作业、应急救援、巡检、文旅及载人运输的实际进展 | 重点收录航线开通、任务执行、试运行、常态化运营及可核验的运行结果 |
| 6 | 国外动态 | 海外监管与标准、企业研发取证、融资订单、基础设施及应用运营 | 按事件发生地和主要适用市场归类；注明国家或地区，海外论文仍归低空学术，同一事件只刊登一次 |
| 7 | 低空学术 | 新发表或网络首发的研究成果，以及有明确价值且标注状态的预印本 | 提炼研究问题、方法、主要发现及限制；征稿、会议报名等归行业机会，不当作研究成果 |
| 8 | 行业机会 | 招标采购、项目申报、招聘培训、赛事、学术征稿及重要活动 | 重点保留参与对象、条件、截止时间和官方入口；已归入其他栏目的事项不重复刊登 |

国内政策、标准、企业、设施与应用分别进入前五栏；境外发生或主要针对境外市场的产业与监管事件进入国外动态。中国企业出海以境外取证、交付、运营等事件为核心时进入国外动态；发生在国内的企业融资不因投资者来自境外而自动归入本栏。国际及国外标准动态进入国外动态时保留标准类型、编号与状态，不在标准栏重复。论文不按国别拆分，统一进入低空学术；以报名、采购或征集入口为核心的机会信息仍归行业机会并标明地域。

栏目名称和顺序固定；当期没有合格内容的栏目直接省略，不设“暂无消息”等占位文字。

每期不预设新闻条数。先收录发布日期较近、已经核验且具有实质新增信息的消息，去重后按实际数量编排；不因达到某个条数就删去合格消息，也不为凑数量或填满栏目而采用旧闻。

低空学术、低空标准和国外动态均按实际合格内容收录，不设固定条数或每日必达数量。每轮必须实际检索海外动态，缺少合格消息时省略栏目。

### 3. 栏目内部排序

来源可靠且符合选入标准后，发布日期较近者优先进入日更稿；各栏目原则上按原始发布日期由近及远排列，同日有明确时刻时按时刻排序。重要政策、重大安全事件、取证和临近截止的机会可作有说明的例外，不用一般旧闻占据较新合格消息的位置。栏目相对顺序保持固定。

## 三、单条新闻格式

每条使用“**事实型标题＋简明摘要＋来源**”格式。全期通常选取1—2张来自入选新闻相应来源的配图，按下述配图规则处理。

```markdown
### 1. [事实型新闻标题]

[摘要正文，通常80—150字，交代时间、主体、地点、具体行动、项目阶段及必要的数字或条件。]

来源：[原始发布机构](原文URL)｜YYYY-MM-DD
```

执行要求：

1. 标题直接说明谁做了什么，避免照搬原文中的宣传性修饰，不使用夸大标题。
2. 摘要优先回答“何时、何地、谁、做了什么、进展到哪一步”。原文没有的信息不补写。
3. 保留影响理解的关键数字、统计口径、适用对象和限制条件；没有重要数字时不强行添加。
4. 正文通常80—150字；重要政策确需补充条件时可适当延长，以事实完整为准。
5. 默认只写事实。确有必要说明意义时，以“观察：”另起一句，标明判断依据；不把推断写成已发生的事实。
6. 来源日期为所引文章或文件的发布日期。事件发生时间另在摘要中交代，不与发布日期混用。
7. 每条至少提供一个已核验的来源。涉及多个来源时，分别列明其支持的信息，不能把所有事实都归于一个并未包含这些事实的来源。
8. 公开稿件不出现“补收”“研究补充”、查漏次数、采集窗口、信源覆盖统计及待审状态等内部编务内容；来源日期、国家或地区、“预印本”“征求意见”等影响事实理解的属性必须保留。
9. Markdown保留原文URL；后续转为公众号排版时，根据实际链接能力调整展示方式，但不能丢失出处。

### 配图选取与图注

- 每期通常选1—2张，优先从入选新闻的政府、企业、项目业主等原始发布中选取与具体事件直接相关的现场、产品、设施或数据示意图片。图片帮助理解消息，不按新闻条数逐条配图。
- 实际打开图片检查内容、清晰度及其与正文的对应关系，排除网页Logo、广告、二维码和无关通用素材。没有合适且可读取的图片时可少配或不配，在内部记录原因，不为凑数量使用无关图片。
- 图片放在对应新闻摘要之后，配简短图注及可点击的来源链接；记录原始图片地址、来源页面和发布机构。原文标明摄影者或供图单位时保留，保留原有水印，不自行去除或冒称原创。
- 示意图、效果图、模型图和实拍照片按实际属性标注；不能用效果图暗示项目已经建成，不能用其他机型或其他地点照片替代本条事件。默认不以AI生成图代替新闻现场图片。
- 遵守来源明示的图片使用条件；标注出处不自动等同取得转载授权。不把来源不明、无法确认关联或明确限制使用的图片直接纳入发布稿。
- 本期排版稿通过Markdown嵌入可核验的原图地址，图注紧随图片。内部附记另记选图、读取及无法使用的候选；公开正文不显示采集过程说明。
- 发布前由用户在微信官方后台确认图片展示、图注和排版，保留用户自行管理及最终发布的流程。

## 四、采集与筛选

### 1. 时间范围

- 统一使用北京时间（Asia/Shanghai）。
- 每期记录本次采集截止时间，默认纳入上次截止时间之后、截至本次截止时间的新发布信息。
- 首期或缺少上次记录时，默认检查截至本次截止时间前24小时的信息。
- 选稿首先看前24小时或本轮新增信息，再看近72小时材料；仅日精度的日期不得强行判定在精确24或72小时内。近7天是查漏窗口，不是默认全部放入正文的范围；更早材料只在重要且仍具现实价值时采用，并在内部说明原因。
- 补收较早但有重要价值的漏采消息时，保留实际发布日期和必要的事件日期，不包装为当天新发生的事件；“补收”“查漏”“研究补充”等编辑流程标签仅记入内部附记，不出现在公开稿件中。
- 已设置每日早间约8:30（北京时间）的补充联网检索与核查任务；公众号发布时间尚未确定。
- 学术检索同时回看近30天新发表或网络首发成果，先选择较近成果，不为维持栏目重复旧文，以降低索引延迟造成的漏采；超出常规新闻窗口的内容保留实际发表时间，采集属性仅记入内部附记。索引新增时间不能替代论文发表时间。

### 2. 来源选择

优先采集政府部门、监管机构、公共资源交易及采购平台、企业官网或官方账号等原始来源。可信媒体报道可作为补充，并尽可能追溯其引用的文件、公告或数据。

原始来源用于确认“谁发布了什么”；对企业技术、性能和商业效果的自述，必要时写明“据该企业披露”，不自动视为独立验证结果。

微信文章、网页或附件无法读取时，进入待核验清单；不能只凭标题、搜索摘要或链接生成可发布的新闻。

### 3. 选入标准

符合栏目范围，并至少具有一项实质新增信息：

- 新出台的政策、规则、标准或明确的实施安排。
- 项目进入招标、中标、开工、试运行或正式运营等新阶段。
- 企业披露新的取证、研发、融资、订单或交付进展。
- 应用场景出现实际任务、航线、运营方式或运行结果的更新。
- 存在可跟进的采购、申报、招聘、培训、赛事或活动机会。
- 新研究提出与低空产业、治理或运行有关、能够准确说明证据与限制的发现。

通常不选入：无实质新增内容的考察交流、泛泛表态、纯宣传稿、重复转载、来源不明的数据及与低空关联较弱的消息。

符合上述范围仅代表进入候选池。常规招投标的正文采用标准从严，避免因公告容易取得而挤占政策和企业实质进展。同一项目的零散配套采购优先合并为一条项目进展；已刊且没有实质变化的标讯进入内部跟踪，不在日报反复出现。重大项目新阶段、关键结果、实质性条件变化或确有临近截止提醒价值的机会可采用，并在内部记录理由。临近截止本身不构成每天重刊的理由。

“首个、首次、最大、领先”等表述须核实比较范围和依据；无法核实时删除修饰，保留可以确认的事实。

### 4. 学术收集与编写

- 中文入口包括知网、万方、国家哲学社会科学文献中心及期刊官网；跨语言发现结合Crossref、OpenAlex和arXiv，最终核对期刊或作者原文。数据库元数据不是论文全文。
- 每日实际搜索中文及英文词组。中文覆盖低空经济、通用航空、无人机、空域治理、低空气象、基础设施、物流、产业与区域经济；英文覆盖low-altitude economy、advanced air mobility、urban air mobility、eVTOL、drone logistics、unmanned aircraft systems，并组合economics、governance、weather risk、climate resilience、noise等主题。
- 选文以对读者的研究或业务价值为准，不把所有无人机算法论文纳入。政策经济、空间布局、运行安全、气象风险、环境影响等均可选入，不只搜索标题中的“低空经济”。
- 记录论文题名、作者、期刊或会议、DOI或预印本编号及版本、原始链接、网络首发和正式出版日期、首次采集日期、发表状态及实际读取范围。按规范化DOI或预印本编号去重，并关联预印本与后续期刊版本。
- 区分正式发表、网络首发与预印本。预印本明确标注“预印本”，不写成已通过同行评议；正式发表也不等于结论已被普遍证实。期刊专题征稿公告不当作新论文。
- 本栏按 `social-science-research-workflow` 的阅读与作者判断规范提炼证据，再适配为新闻摘要。依据为用户提供的 `skills/social-science-research-workflow/SKILL.md（可选本机安装入口）`，以及 `references/literature-reading.md`、`references/author-judgment-writing.md`、`references/writing-validation.md`；2026年10月19日已读取。后续无法访问该本机路径时，执行本节已固化的要求并记录技能入口缺口，不声称当轮已重新调用。
- 每篇摘要正文始终为一个自然段，通常80—150字，必要时可至200字。标题、来源、真实发表日期、DOI和图注可另列。一个自然段围绕一个核心问题或发现展开，不拆成“背景、方法、结论、启示”等小栏目，也不把完整阅读笔记压成要素罗列。
- 动笔前在内部明确：论文回答什么问题，作者作出什么判断，哪些原文证据足以支持它。公开段落可从研究问题或有作者归属的核心发现切入，再安排理解该判断所必需的证据；不规定所有文章使用同一句序。证据不足时缩小或删除主张，不用抽象概念、套话或修辞补齐。
- 样本、方法和结果围绕同一研究问题、对象及范围衔接。按理解需要交代时间与地域、研究对象、样本或材料、核心比较或设计，不只堆叠DID、IV等方法名称；不在短讯中罗列全部变量、检验和技术细节。理论、定性、实验、计量及模拟研究按各自证据性质表达，不强行改写为经济学因果研究。
- 主要发现写清具体对象、关系、方向及必要条件，保留“作者发现、估计、推导、模拟”等归属。相关性不写成因果，预测和仿真不写成实际运营效果；异质性不自动等于机制，代理变量、分组或系数变化不单独当作机制证实，方法名称和显著性也不代表识别假设已经成立。
- 研究含义只解释已核验发现对核心问题增加、修正或限定了什么认识。文献缺口、相对既有研究的贡献和机制解释均须有已读原文依据；未完成检索不称“首次”或“填补空白”。不自行增补融资效果、政策收益、福利或产业前景，不机械列满理论、实践和政策意义。
- 保留真正改变判断或外推的关键边界，例如样本代表性、测量口径、识别前提、场景或参数假设；不套用每篇相同的免责声明。重要边界优先于背景套话。正面立论，使用具体主体和行为、清楚的句子与统一术语，删去假对立、装饰性评价、重复结果和自动拔高的结尾。
- 内部阅读卡记录研究问题、动机、设计及理由、数据或材料、发现、贡献、限制、原文锚点、采用用途和下一步；未核验或不适用的项目如实标记，不为填满栏目补造。区分作者主张（SOURCE CLAIM）、阅读解释（CODEX INTERPRETATION）、跨文献综合（CROSS-PAPER SYNTHESIS）与编辑推断（OUR INFERENCE）；公开摘要默认报道作者主张，标签和阅读卡不进入正文。
- 内部按实际读取范围分证据：A为已核对相关全文或一手材料且有页码、章节、表图、公式或附录锚点；B为已核验正式摘要，仅支持摘要明确陈述的暂定描述；C为元数据、搜索片段或二手提及，仅用于发现。打开PDF不等于全文核验，局部阅读不称全篇精读。无相关全文锚点的分析记 needs-verification，未完成检索的缺口记 needs-search。
- 本任务输出仍为供人工审核的新闻待审稿。只读摘要时仅在“基于论文摘要”的明确标注下概括摘要内容，不补写全文才可确认的模型、机制、稳健性或局限；只有搜索片段时不刊登。需要全文才能支持的强结论暂缓采用。正式学术成稿及核心跨文献综合遵守skill的 source_level: A、status: accepted 门槛；AI新建笔记先记 waiting-review，不自行改为人工接受，也不把新闻待审稿冒充正式学术综合。
- 元数据、发表状态与证据等级分别核对。正式发表不等于结论普遍成立，预印本不写成通过同行评议；保留题名、作者、原始发表日期、DOI或版本及原文链接。更正、撤稿和后续期刊版本继续关联跟踪，必要时修订此前摘要。
- 写作性调整前按skill核对1—3个与段落任务相关的真实原文参照，借鉴判断、证据与含义之间的组织方式，不套句式，也不以范文替代被报道论文的证据。内部自行核查主张与证据、语言和边界，直接交付修正后的段落；检索记录、证据锚点和重要缺口留在内部附记，不随每条短讯附固定自检清单。

- 全国标准信息公共服务平台作为总入口，结合国家标准全文公开、行业标准、地方标准、团体标准、企业标准平台；追溯市场监管总局、民航局、工信部、交通运输部、气象局及地方发布部门的公告与附件。国际补充关注ISO/TC 20/SC 16和ASTM F38。

- 立项不等于发布，征求意见稿不等于现行标准，发布不等于当天实施；备案日期不等于发布日期。区分待实施、现行及废止，保留地方适用地域与具体适用对象。
- 团体及企业标准保留发布主体和自我声明性质，不写成国家强制要求或政府认证；国际标准、国外标准及ASTM工作项目分别标明状态，不能自动写成国内适用的监管要求。
- 标准体系建设指南、法律法规、适航审定文件、技术标准分别记录文件类型，避免同一事项跨栏目重复。未确认RSS或公开API的入口，按网页公告/目录检索处理，不编造订阅地址。

## 五、去重、归类与事实核验

### 1. 去重与连续跟踪

- 同一事件被多个来源报道时，合并为一条，优先引用原始来源。
- 同一事件只放在一个最相关的栏目，不在多个栏目重复刊登。
- 归类按新闻核心新增事实判断，不仅根据发布机构或标题关键词判断。
- 同一项目的签约、招标、中标、开工、试运行和正式运营属于不同进展；确有新信息时可再次报道，并简要交代前序阶段。
- 新进展优先于重复介绍项目背景。一般机会信息不每天重复发布；截止时间变更、条件调整或临近截止确有提醒价值时，可注明更新或提醒。

### 2. 核验重点

| 核验对象 | 必须保留的区别 |
| --- | --- |
| 时间 | 发布日期、事件发生日期、政策生效日期、报名或申报截止日期 |
| 主体 | 母集团与子公司、采购人与中标人、主办方与承办方 |
| 金额 | 项目总投资、采购预算、最高限价、中标价、融资额；保留币种和单位 |
| 阶段 | 拟建、签约、招标、中标、开工、测试、试运行、正式运营 |
| 航线与应用 | 演示飞行、试飞、试点运行、常态化运行及商业运营 |
| 政策状态 | 征求意见、正式印发、开始实施及政策解读 |
| 证照与资质 | 证件准确名称、颁发机构、适用对象与范围；不同审定或许可不互相替代 |
| 统计数据 | 时间区间、地区范围、统计对象及累计值或当期值 |
| 学术成果 | 正式发表、网络首发、预印本；摘要与全文；相关性、因果及模拟结果 |
| 标准文件 | 标准层级与编号；草案、已发布待实施、现行、废止；发布日期、实施日期及备案日期 |

发现来源冲突时，核实是否因时间、范围或口径不同导致。冲突未解决前不直接采用争议结论，可暂缓刊登或明确保留差异。

## 六、编稿与审核流程

1. 采集新增消息，保留来源链接及原始发布日期。
2. 检查正文与附件，筛除无实质信息或无法核验的内容。
3. 按事件去重，关联已有项目记录，并确定唯一栏目。
4. 生成标题和摘要，核对主体、时间、数字及项目阶段。
5. 按固定栏目顺序编排，省略空栏目。
6. 根据当期已选消息，生成体现2—3条不同动态的标题及简短今日总结。
7. 输出待审稿与内部待核验清单，两者分开；待核验内容不混入公开正文。
8. 人工审核后发布，并记录已发布事件，供后续去重。

第一阶段默认自动采集、整理和编稿，人工审核发布。本文件确定内容编辑规则，不代表已经配置公众号接口或启用自动发布。

发布前检查：

- [ ] 今日总结为一段，通常2—3句话、100—180字，覆盖几类重要动态，且每个判断都能对应当期消息。
- [ ] 标题体现当期2—3条不同动态（重要消息不足时按实际数量），最重要的消息在前，且与正文事实及进展阶段一致。
- [ ] 栏目名称、顺序及单条新闻格式符合本规则。
- [ ] 没有重复事件、旧闻冒充新进展或空栏目占位。
- [ ] 每条摘要与已读取的原文一致，没有补造信息。
- [ ] 低空学术每篇摘要正文仅一个自然段，主张有相称证据与内部锚点，摘要/全文读取范围、作者归属和发表状态准确。
- [ ] 主体、日期、数字、金额口径及进展阶段准确。
- [ ] 来源机构、发布日期及原文链接齐全；有截止时间的机会信息仍然有效。
- [ ] 清除了模板占位符、演示文字、“补收”“研究补充”等流程标签和内部编辑备注。
